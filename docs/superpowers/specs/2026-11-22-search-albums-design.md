# Search iCloud album lookup

## Intent and approach
Extend `/search` with album names and optional public iCloud buttons. Use an explicit registry and saved import provenance first; date-only mapping cannot reliably identify imported products and per-product manual backfill is unnecessary. The user authorized specification, planning and immediate execution together.

## Contract
- Registry entries contain unique source album ID, display name (1–100 characters), optional HTTPS `www.icloud.com/sharedalbum/#<token>` or `photos.icloud.com/shared/album/<token>` URL (maximum 1,000 characters; fragment accepts letters, digits, `_` and `-`), and optional inclusive Gregorian `YYYY-MM-DD` start/end dates. Both dates must be present together, valid, and ordered. Dates mean **date added to the shared album**, in Bangkok calendar dates, not capture dates. Maximum two ranges may overlap on any day. At most 200 entries.
- Registry is stored in existing revision-controlled settings as `ICLOUD_ALBUMS`, default empty. Connections settings API can update it. Changing the active upload album and LINE configuration commands are out of scope.
- For a product with matching saved D1 product ID, Airtable record ID, base and table, use the saved source album ID. A known import with an unmapped source stays unknown; do not fall back to a potentially incorrect date. Conflicting import provenance stays unknown. Without matching provenance, use strict Airtable Upload Date against ranges.
- One match: show the album name in black (`#2C2C2C`), right-aligned directly beneath the upload date, without an album heading, and its optional website button labelled `เปิดบน iCloud.com`. Two-candidate buttons use `เปิดบน iCloud.com 1` and `เปิดบน iCloud.com 2`, preserving the candidate number when one URL is absent. Do not promise a Photos-app redirect. Two date matches: show both names and explain `สินค้านี้อาจอยู่ในอัลบั้มใดอัลบั้มหนึ่ง`, with one button per available URL. Both names remain black and right-aligned under the date; the uncertainty explanation remains a separate readable full-width note. A mapped name without URL remains useful.
- Missing/invalid date, no mapping, or unmapped source: `ไม่สามารถระบุอัลบั้ม iCloud ของสินค้านี้ได้`. Dependency failure: `ตรวจสอบอัลบั้ม iCloud ไม่สำเร็จ กรุณาลอง /search อีกครั้ง`. Product details and Airtable button remain available. Never expose exceptions, signed URLs or secrets in error text. Optional enrichment failure must not fail the command or be serialized as a thrown custom Error.
- During the approved external-browser trial, `/search` Airtable and iCloud URI actions add `openExternalBrowser=1` via URL query parameters, before any fragment. Preserve existing query values and album tokens. Stored canonical URLs and source-ID derivation remain unchanged. Soldout and other commands are outside the trial. Native app handoff remains device-dependent.
- Apply album enrichment to `/search` only; soldout cards unchanged. Include album information in Flex alt text. Keep existing Airtable action; append distinct album actions.
- No album dates or URLs are invented or published automatically. Configure only verified album metadata. Use exact import source identities only where established; unverified source mappings stay unknown. Source-only entries with null dates may be used for mock albums to avoid contaminating historical date fallback. Public URL availability and historical Airtable date semantics remain data prerequisites, not inferred facts.

## Validation and rollout
Test strict calendar dates, inclusive boundaries, two overlaps, rejected triple overlap, malicious URLs, provenance priority and target isolation, unknown mappings, D1 outage, rendered buttons and fallback. Test settings backward compatibility and actual command dependency wiring. No deployment or remote changes in this task. Zero bugs cannot be guaranteed; report verification limits honestly.
