03 / Critical dependency

Prove iCloud first

Apple offers no supported server API or webhook for unattended Shared Album ingestion. Cloudflare must reproduce requests used by public album webpage.

Delivery gate

Unsupported connector

Do not build production import flow on assumptions. Phase 0 must prove connectivity, stable ordering, checkpoint behavior, streaming download, deduplication, and token redaction from Cloudflare.

  • Public album URL acts like weak secret.
  • Images may be reduced to 2048 px long edge.
  • Metadata may be lost in downloaded copies.
  • Shared Album limit is 5,000 items; rehearse rotation before limit by creating a new active album and retaining old album as archive.
  • Endpoint may change without notice.
Pass

Continue iCloud adapter

All controlled tests pass at production-sized volume. Downstream implementation proceeds.

Fail

Replace image source only

Use direct upload or supported cloud-folder source. Keep D1, R2, Workflows, Airtable, Docs, and LINE design.

04 / Workflow A

Upload to Airtable

Scheduled snapshot starts after 30-minute upload cutoff. First run starts at configured date. Later runs process unseen Apple IDs and verify content hashes.

Product ID allocation

Setup bootstraps D1 once from highest valid Airtable ID while imports are disabled. D1 then becomes sole authority; health checks block imports if Airtable advances outside system. Failed or deleted IDs are never reused.

Retry behavior

Five exponential-backoff attempts. /upload skips succeeded groups, retries failed groups with fresh cycle, and processes new groups.

Failure compensation

Delete partial Airtable row. Keep R2 originals. Preserve burned ID. Report group position, source range, attempted ID, reason, and link.

Checkpoint

Advance when all groups reach terminal state. Failed records remain explicit and retryable rather than becoming unseen work.

Claude caption call

Claude Opus 5 receives verified Airtable text only. No image input. Exactly three editable Thai drafts keyed by Product ID. Expected 22–24 products fit one structured request.

Master template

Customer controls branding, title, formatting, instructions, and suffix. Workflow copies template once at start; retries reuse that copy, while later edits affect future runs only.

One final document

Temporary document is verified first. D1 stores one final Google Doc ID per Publication Run. Retry reuses valid sub-results.

Whole-run block

Incomplete data

No Google Doc is created. LINE reports every Product ID and missing field, includes Airtable link, and instructs staff to fix data, set run to Ready, then run /docs.

07 / Operator surface

LINE commands

One allowlisted admin group. Every member may run commands. Worker validates signatures. D1 deduplicates webhook events and one-time callbacks.

Approve writes Inventory Status = Out, Sold Price, Sold At, and Sold By. Existing listing prices remain unchanged.

/revert — safe latest-action rollback

Targets latest reversible command in same group. Requires second confirmation. Runs only when current Airtable values still equal recorded after-state, preventing overwrite of newer edits.

/search A-XXXX — inventory lookup

Returns Product ID, inventory state, upload date, and Airtable row link. Unknown ID receives Thai not-found response.

/upload and /docs — manual workflow triggers

Start or resume durable jobs. Import skips successful groups. Publication reuses valid sub-results and never creates duplicate final document.

/help — operator reference

Returns commands and accepted examples in Thai.

Why pending state exists

Approve button is separate LINE event. D1 binds it to requester, group, Product ID, price, old values, expiry, and one-time token.

Already sold

Reject without overwrite. Show existing sold price, sold date, sold by, and Airtable link. Missing legacy sale data is labeled unknown for direct Airtable correction.

Confirmation expiry

Pending soldout and revert confirmations expire after 10 minutes. Duplicate or expired callback does nothing.

Audit

Immutable event records actor, action, correlation ID, before state, after state, and timestamp.

08 / Production controls

Secure and observable

Customer owns accounts and credentials. Secrets stay in Cloudflare. Logs carry enough context to act without exposing album tokens or image access URLs.

Security baseline

  • Validate LINE x-line-signature
  • Restrict actions to allowlisted group
  • Keep R2 bucket private
  • Use short-lived Airtable attachment URLs
  • Limit Google service account to publication folder
  • Never log tokens, album link, signed URLs, or images

Initial monitoring

  • Cloudflare structured logs
  • D1 workflow and audit history
  • LINE success and actionable failure alerts
  • Usage alarms for R2, Images, Workflows, Claude
  • No Sentry until native telemetry proves insufficient
